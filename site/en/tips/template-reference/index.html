Template variables and rules

Use variables to fill in a paper’s details. Use rules to choose a different outline for a collection or tag.

On this page Template variables Database properties Template rules

Template variables

In Zotero, open Settings → Zotero2Notion → Templates and enter variables in the Markdown editor with their square brackets. For example, [title] ([year]) becomes Attention Is All You Need (2017). Click Preview to try it with the selected paper or with sample data.

VariableWhat it adds to the note
[title]Paper title, from the Journal Name field.
[authors]All authors, separated by semicolons.
[authors_short]First author, followed by “et al.” for papers with multiple authors. Displays “Unknown author” if there are no authors.
[year]Publication year.
[url]The paper’s URL as written in Paper URL.
[paper_link]A Markdown link labeled “Paper”. Displays “Paper URL unavailable” if the URL is missing.
[zotero_link]A Markdown link labeled “Zotero” that opens the item in your library.
[zotero_notes]Notes attached to the Zotero item. Put this marker once on its own line, outside a code block, where you want the notes to appear.

Each nonempty child note gets its own toggle under Zotero Notes. An item without notes gets no empty section. Imported notes stay in sync, so keep your own writing outside those toggles.

Database properties

Put a property name in brackets to include its value when the plugin first fills in the outline. For example, [Abstract] inserts the abstract. You can also use a lowercase name with underscores, so [Full Citation] and [full_citation] produce the same citation.

GroupDefault property names
Paper details[Journal Name], [Short Title], [Item Type], [Abstract], [Authors], [Editors]
Publication[Publication], [Year], [Date], [Place], [Proceedings Title], [Series Title]
Citations and links[Full Citation], [In-Text Citation], [Citation Key], [DOI], [Paper URL], [Zotero URI], [Zotero Key]
Library and workflow[Status], [Project], [Tags], [Collections], [Date Added], [Date Modified], [File Path], [Extra]

You can use a mapped field’s default name or the name of its Notion property. Custom properties work the same way. For a text property named Reading goal, use [Reading goal] or [reading_goal]. Check the value on the new Notion page. Preview uses Zotero or sample data.

The plugin can read title, text, number, select, status, multi-select, date, checkbox, URL, created time, and last edited time. Dates use the start value. Multi-select values are separated by semicolons.

For an unsupported property type such as relation, rollup, or formula, the variable produces an empty value. An unrecognized name stays in brackets. Values are inserted once, so brackets inside a value remain literal.

Template rules

Under Templates → Default template, choose the outline to use when no rule matches. Edit template selects the outline you want to edit. Changing an outline or rule preserves text already written on existing pages.

  1. Add a rule

    In the Zotero2Notion settings, open Template rules → Add rule. Choose Collection or Tag, fill in the condition, and pick an outline under Template.

  2. Choose what to match

    A collection rule covers the selected collection and its subcollections, even if you rename the selected collection later. A tag rule matches the exact tag name, including capitalization.

  3. Put the most specific rule first

    The plugin reads rules from the top and uses the first active match. Use the up arrow to raise a rule’s priority. It skips incomplete or disabled rules.

Example rules for seminar papers

Set the first rule to use Paper review for the tag review. Set the second to use Section summary for the Seminar collection.

A seminar paper tagged review gets Paper review. An untagged paper in Seminar or one of its subcollections gets Section summary. A paper matching neither rule uses your default template.
